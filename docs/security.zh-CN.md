# 后台输入与权限安全规范

## 核心原则

- 所有客户端输入均不可信；前端隐藏、禁用和类型控件不能代替服务端验证与授权。
- 每个接口必须同时完成身份认证、操作权限、对象权限、字段白名单、类型与业务范围校验。
- 控制器只能写入验证后的数据；禁止将 `$request->all()` 整体传给 `create()`、`update()` 或 `fill()`。
- Eloquent模型必须声明明确的 `$fillable`；不得使用 `$guarded = []`。

## 新增功能统一要求

1. 写接口必须配置稳定的 `admin.permission:*` 权限码；超级管理员专属能力使用 `admin.super-admin`。
2. 创建和更新分别声明字段规则。字符串限制长度，整数限制范围，状态使用枚举，关联编号使用 `exists`。
3. 数组必须设置 `max`，标识数组成员必须设置 `integer`、`distinct` 和 `exists`。
4. JSON配置必须限制大小、允许的嵌套键、值类型和枚举；未知键不得直接进入数据库。
5. 非超级管理员不得授予超级管理员角色、不得修改超级管理员账号、不得授予自己没有的权限或敏感权限。
6. 多表写入、关系同步和批量操作使用事务；敏感操作写审计日志且不得记录密码、密钥或2FA密钥。
7. 批量接口限制最大条数、去重并确认全部目标属于当前业务范围。
8. 上传文件验证真实文件类型、MIME、大小和尺寸，文件名由服务端生成，路径限制在允许范围。
9. 新模块必须增加Feature测试，覆盖未登录、无权限、额外字段、错误类型、越权对象、越级授权、无部分写入和合法请求。

## 当前后台约束

- 管理接口先经过 `auth:sanctum` 和 `admin.user`，操作权限由 `admin.permission` 再次验证。
- 用户角色和角色权限分配统一使用 `PrivilegeAssignmentGuard` 防止权限提升。
- 用户、角色、权限、菜单和配置模型使用明确的 `$fillable` 字段白名单。
- 角色、权限、菜单关系数组最多500条；重复标识校验失败。
- 权限授权以稳定权限编码和路由上的 `admin.permission:*` 服务端校验为准；权限父级循环、无效菜单编号和超限数组均由服务端拒绝。
- 权限资料和 `permission_menus` 关系必须在同一事务保存；系统权限编码不可修改，有子权限或已分配角色的权限不可删除。
- 登录失败按 IP、用户名和二者组合进行 24 小时风险累计；组合达到 5、10、20 次失败时阶梯锁定。同一 IP 尝试至少 10 个不同用户名时自动封禁 2 小时。
- 2FA 挑战绑定创建时的 IP 和 User-Agent，最多失败 5 次，验证成功后必须原子消费；正式环境超级管理员强制使用 2FA。
- 风险事件通过 `AdminSecurityRiskDetected` 提供扩展点，宿主监听器不得把密码、Token、验证码或 2FA 密钥发送到外部告警通道。

## 评审清单

- [ ] 绕过前端直接构造HTTP请求时，服务端仍拒绝未授权操作。
- [ ] 提交内部字段、未知字段或错误类型时不会写入。
- [ ] 操作者不能创建比自己权限更高的账号或角色。
- [ ] 关联ID不存在、停用、重复或数量超限时请求失败。
- [ ] 事务失败时没有部分数据或关系残留。
- [ ] 成功与拒绝场景有自动化测试；敏感成功操作有审计记录。
